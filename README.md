# p0-w1-d3-t3 · Доступная анкета

> Тип: синтез (дни 1 + 2 + 3) · Репозиторий: один отдельный

## Контекст

Возвращаешься к форме-анкете, но теперь её должно быть реально возможно заполнить человеку со
скринридером и без мышки. Это задача на стыке всей недели: семантика дня 1, формы дня 2,
доступность дня 3.

```
д1 семантика + д2 форма + д3 доступность
┌──────────────────────────────────────────────┐
│ <main> анкета                                │
│   fieldset → legend = группа для скринридера │
│   label/for = имя поля                       │
│   aria-describedby → подсказка к полю        │
│   aria-live → сообщение об ошибке вслух      │
└──────────────────────────────────────────────┘
проверка: пройти форму только с клавиатуры
```

## Что нужно сделать

Доступная семантическая форма: каркас и `fieldset`/`legend` (дни 1–2), плюс доступность дня 3 —
каждое поле с именем, подсказки через `aria-describedby`, сообщение об ошибке, объявляемое
скринридером (`aria-live`), полная проходимость с клавиатуры. Вся валидация — нативная (день 2),
без JS.

## Релизы

### Release 1 — доступная структура
Форма на `fieldset`/`legend`, все поля с `label`/`for`. Пройти Tab’ом от первого поля до кнопки —
порядок логичный. Закоммитить.

### Release 2 — подсказки и группы
К полям со сложным форматом привязать подсказку через `aria-describedby` (id текста-подсказки).
Проверить скринридером, что подсказка читается вместе с именем поля.

### Release 3 — доступные ошибки
Сделать зону под ошибки с `aria-live="polite"`, чтобы при нативной валидации сообщение
объявлялось. В `A11Y.md` описать, как ты проверяла форму с клавиатуры и скринридером.

## Критерии приёмки

* Форма полностью заполняется и отправляется только с клавиатуры.
* У каждого поля есть имя; сложные поля имеют `aria-describedby` с подсказкой.
* Группы полей оформлены `fieldset`/`legend`, читаются скринридером как разделы.
* Нативная валидация работает, JS не используется.
